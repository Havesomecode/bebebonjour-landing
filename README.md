# Bébé Bonjour landing

First-party Vite landing for `https://bebebonjour.com`, with dormant local and
synthetic verification clients kept outside the public entrypoint.

## Current production boundary

- The landing sells one product: a €39 announcement page (text, Cedar narration,
  two corrections, 12 months online), paid once. Order flow shown to visitors:
  describe → we read the request → pay → the announcement arrives.
- All four public CTAs use `/delivery`. Vercel proxies `/delivery/*` and `/announcements/*` to the owned
  Railway intake at `https://api-production-c9013a1c.up.railway.app`, so the form, order
  links and announcements stay on `bebebonjour.com`. Those pages send their own
  Content-Security-Policy; the landing one excludes them.
- An operator reads every request before any generation; the customer pays €39
  through the Stripe Checkout link emailed after that, and generation starts only
  after verified payment. The order form, payment and emails live in the app
  repository (`bebebonjour-app`), not in this landing.
- `/exemple/amal/` is the public example: a static copy of the real Amal
  announcement produced by the generator (Codex text, Cedar voice), with
  `noindex`. It carries no Convex URL or capability token.
- The canonical private Operations console is not a customer-facing status portal
  and must never be linked from the public landing.
- The announcement is a non-indexed shareable capability: anyone with its link
  can view it. Email addresses and review links remain private. Never embed a
  customer capability, review URL, or operator URL in the public landing.
- The optional interest list posts to the same-origin `/interest/subscribe` proxy;
  `/interest/confirm` and `/interest/unsubscribe` also proxy to Railway. The backend
  owns confirmation, unsubscribe and retention; local tests stub the request.
  Its pages send their own CSP. The landing CSP and `/demo`/SPA rewrites remain in place.

## Local-only customer flow

Use Node 20.19+ or 22.12+ and install both repositories with `npm ci`.

Start the memory-only API from `../bebebonjour-app`:

```bash
npm run dev:customer-flow
```

Then start this landing:

```bash
npm run dev:local
```

Open `http://127.0.0.1:5173`, use only invented details and an email ending
in `.test`, and stop both processes when finished. The opaque intake token is
kept in tab-scoped `sessionStorage`; it is never placed in a URL. The browser can
create or inspect its own job and request its reusable checkout session, but it
cannot record payment, editorial approval, publication, or delivery.

The TEST-A server uses memory and local adapters only. It sends no provider
request, email, payment, deployment, or production mutation.

## Dormant hosted compatibility client

The excluded compatibility client can target one immutable HTTPS API candidate
without loosening the loopback default. It is not part of the public customer
journey. Configure its exact canonical base URL only for bounded verification:

```bash
VITE_FULFILLMENT_API_BASE_URL=https://bebebonjour-fulfillment.vercel.app/api/customer-flow
```

The canonical hosted base is pinned in executable source. Any other HTTPS value,
including the landing's own origin or an equal operator-provided override, safely
disables the TEST-A client instead of activating a different host.

The hosted API access token is never a Vite variable. The browser asks the
operator for it on the first hosted command, sends it as
`X-Test-A-Access-Token` on every `/v1` request, and retains it in memory only
until the page is reloaded. Never place that token in an environment file,
build command, URL, browser storage, log, or committed asset.

This repository pins Vercel's `Content-Security-Policy` `connect-src` to
`'self'` only. The dormant client above is excluded from the public entrypoint. It
does not activate a hosted endpoint, deploy, publish, send customer email, or
permit live payment.


## Synthetic workflow demo

`/demo` is a static, unmistakably synthetic playback of the canonical TEST-A
workflow. It accepts only the two built-in fictional profiles, performs no provider
or analytics request, and offers a one-click deterministic reset. Its bundled
manifest and announcement pages are generated by the sibling app repository:

```bash
cd ../bebebonjour-app
NODE_NO_WARNINGS=1 npm run demo:export -- ../bebebonjour-landing/public/demo
```

The committed artifact keeps both `/demo/announcements/amal/fr/` and
`/demo/announcements/bayane/fr/` reachable. `/demo` is not linked from the landing.

## Fonts

Newsreader and Instrument Sans (OFL) are self-hosted in `public/fonts/`. The proxied
`/delivery` pages load the same files from `/fonts/`, so keep those paths stable.

## Deployment

Pushing `master` deploys production on Vercel (`bebebonjour.com`). Check the
live page on desktop and mobile after each push.
